# Our own Nord Shiki theme for code blocks

The spec called for Shiki's built-in `nord` theme on code blocks, but that Shiki theme breaks two of the Theme's rules. Its comment color (#616e88) isn't one of the 16 Nord colors, and five of its token colors fall below WCAG AA contrast on its own nord0 background: comments, plus nord15, nord12, nord11 and nord10. The axe scan of a Post with code fails on them. So code blocks use our own Shiki theme, `src/shiki/nord-theme.ts`: a copy of the built-in one (MIT licensed, from Nord Visual Studio Code) with only those five colors swapped for Nord colors that pass. Comments become italic nord4, nord15, nord12 and nord11 become nord13, and nord10 becomes nord9. This holds for any code an Adopter writes, not just the filler content, and adds no dependency. The cost is that upstream fixes to the built-in theme no longer arrive, which matters little in a theme the Adopter owns outright. Code blocks stay dark in both Color modes. A light Shiki theme stays out of scope.
